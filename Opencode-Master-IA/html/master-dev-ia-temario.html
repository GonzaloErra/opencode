Pensamiento Computacional y Resolución de Problemas

Habilidad fundamental para todo desarrollador que consiste en descomponer problemas complejos en partes más pequeñas, reconocer patrones y diseñar soluciones algorítmicas. Es el puente entre el problema real y su solución programática.

Deberías saber (basado en fuentes ISTE, MIT, LibreTexts, DEV Community):
  • Definición oficial: "Pensamiento involucrado en formular problemas cuyas soluciones pueden representarse como pasos computacionales y algoritmos" (Jeannette Wing, Columbia University) - citado por ISTE y ACM
  • Cuatro técnicas fundamentales: Decomposición, Reconocimiento de patrones, Abstracción, Diseño de algoritmos
  • Aplicar divide y conquistar para resolver problemas complejos
  • Validar casos borde y casos de entrada
  • Diferenciar entre pensar en binario vs pensamiento computacional significativo
  • Computational thinking transcends mere programming - no equivale a pensar en binario, ya que las computadoras carecen de capacidad de pensamiento

Fundamentos de la Programación

Conceptos universales que se aplican a casi cualquier lenguaje de programación: variables, tipos de datos, estructuras de control, funciones, modulación de errores. Estos conceptos son paradigmáticos y no lenguaje-específicos. Un programa es una secuencia de instrucciones que el computador sigue para realizar una tarea.

Deberías saber (basado en DEV Community guides, OpenStax, Scaler, IEEE Computer Society):
  • Declaración de variables con let, const, var y sus diferencias de scope (scope chain, hoisting, temporal dead zone)
  • Tipos de datos primitivos vs estructurados: numbers, strings, booleans, arrays, objects, null, undefined, symbol, bigint
  • Estructuras de control: if/else, switch, bucles for/while/do-while con sus casos de uso y flujos de ejecución
  • Creación y uso de funciones: parámetros, retorno, scope (local vs global), closure, llamada por valor vs referencia, inmediatamente invocada función IIFE
  • Manejo básico de errores: try/catch en lenguajes modernos, patrones de error handling (error first callback, promises .catch(), try/async-await)
  • Principio DRY (Don't Repeat Yourself) y escritura de código limpio: funciones pequeñas, nombre descriptivo, sin duplicación
  • Comentarios: propósito vs implementación, comentar el "por qué" no el "qué", comentarios significativos

Introducción a los Lenguajes de Programación

Exploración de paradigmas de programación y cómo diferentes lenguajes soportan diferentes estilos. Comprensión de POO, programación funcional, asincronía y modularidad. La elección del lenguaje depende del proyecto y dominio. Los lenguajes pueden ser multiparadigma y no se limitan a un solo paradigma.

Deberías saber (basado en Roadmap.sh, GitHub Roadmaps, CIS-Team roadmaps, ACM Curriculum):
  • Paradigmas principales: Imperativo (secuencia, control, estado), Declarativo (qué hacer, no cómo), Orientado a Objetos (OOP), Funcional, Lógico, Visual
  • Principios OOP: Encapsulamiento (ocultamiento de información), Herencia (herencia de clase, herencia prototípica), Polimorfismo (polimorfismo subtipo, ad-hoc, parametric), Abstracción - los 4 pilares fundamentales
  • Programación funcional: funciones de primera clase, map/filter/reduce/reduceRight, inmutabilidad, pure functions, higher-order functions, currying, composición de funciones
  • Programación asíncrona: callbacks, promises, async/await en JavaScript/Python, event loop, task queue, concurrency model
  • Gestión de dependencias: npm, pip, requirements.txt, gestor de versiones y conflictos de versiones, semver (versión semántica)
  • Modularidad y creación de paquetes/reutilización de código, namespaces, módulos, packages
  • Comparación de lenguajes: Python vs JavaScript vs Java vs C++ vs Rust - casos de uso y ecosistemas

Fundamentos de Sistemas y Redes

Cómo funcionan los sistemas computacionales y las redes que los conectan. Modelo cliente-servidor, protocolos HTTP/HTTPS, direccionamiento IP, DNS, y cómo las aplicaciones comunican a través de redes. Explica cómo las aplicaciones se comunican a través de redes usando modelos de comunicación.

Deberías saber (basado en roadmaps de CS, MIT OpenCourseWare, Kurose & Ross, Tanenbaum):

  • Concepto de API: REST vs GraphQL vs SOAP, endpoints, recursos y representaciones, HTTP methods, status codes, error handling
  • Comunicación entre procesos y sobre redes locales/internet: sockets, TCP/UDP, capas de aplicación, transporte, red

Buenas Prácticas

Disciplinas y estándares que aseguran la creación de software de calidad, mantenible y escalable. Incluye código limpio, principios SOLID, testing, debugging, y consideraciones éticas en el desarrollo tecnológico. Las buenas prácticas evolucionan con la industria.

Deberías saber (basado en principios industriales, guías SOLID, Clean Code, Code Complete):
  • Principios SOLID: Single Responsibility (SRP), Open/Closed (OCP), Liskov Substitution (LSP), Interface Segregation (ISP), Dependency Inversion (DIP) - los 5 principios con ejemplos de código
  • Clean Code: nombres descriptivos, funciones pequeñas (≤ 10-15 líneas), comentarios significativos, indentación consistente, nombrado consistente
  • Debugging: lectura de trazas de error, uso de debuggers (print/console logging estratégico, step-through debugging), REPL debugging
  • Conceptos de testing: unit tests (pruebas unitarias), integration tests (pruebas de integración), E2E tests (pruebas end-to-end), TDD (Desarrollo Orientado a Testes), BDD (Desarrollo Dirigido por Comportamiento)
  • Gestión de deuda técnica: identificar, refactorizar y prevenir acumulación de código problemático, medición de deuda técnica
  • Ética en el desarrollo: privacidad de datos, sesgos algorítmicos, accesibilidad (WCAG), impacto ambiental (carbon footprint del código), responsabilidad social
  • Code Review: procesos de revisión de código, feedback constructivo, aprobaciones, checklist de revisión

FASE 2: Desarrollo con Inteligencia Artificial

Introducción a la IA

Campo de la informática que se enfoca en crear sistemas capaces de realizar tareas que normalmente requerirían inteligencia humana. Incluye aprendizaje automático, razonamiento, percepción, procesamiento del lenguaje natural y toma de decisiones. Los sistemas de IA modernos se basan en modelos estadísticos y reconocimiento de patrones. La IA se divide en IA estrecha (ANI) y IA general (AGI), siendo la actual IA estrecha.

Deberías saber (basado en AI Engineer Roadmap 2026, IBM Watsonx, Scaler Academy, Andrew Ng Coursera):
  • Diferencia fundamental entre IA tradicional (sistemas basados en reglas explícitas, sistemas expertos) vs IA generativa (modelos que aprenden patrones de datos y generan nuevo contenido), la diferencia entre discriminativa vs generativa
  • Breve historia: Taller de Dartmouth 1956 (nacimiento de la IA), "AI winters" de los años 70-80 y 90 (inviernos de IA), renacimiento desde ~2012 con deep learning y redes neuronales profundas, transformación con transformers en 2017 (Attention is All You Need)
  • Tipos de aprendizaje automático: Supervisado (ej. regresión lineal, clasificación con labeled data, 80% uso en la industria), No supervisado (clustering, reducción de dimensionalidad, k-means, PCA), Por refuerzo (agent learns through rewards/re penalties, RLHF - Reinforcement Learning from Human Feedback)
  • Papel fundamental de los datos: calidad sobre cantidad, limpieza de datos, features engineering, sesgo en datasets que puede propagar a modelos (garbage in, garbage out), data versioning, data pipelines
  • Pilares técnicos: Datasets públicos (Kaggle, UCI, MNIST, CIFAR), dato sintético para augmentación, GPUs/TPUs para entrenamiento paralelo (CUDA, cuDNN), cloud computing (AWS SageMaker, Google Colab, Azure ML, Databricks) para escalar, MLOps
  • Mitos vs realidades: IA no tiene conciencia ni sentimiento, no reemplaza completamente a humanos (augmenta en lugar de sustituye), limitaciones actuales incluyen alucinaciones (hallucination rate), sesgo, costo computacional, necesidad de supervisión humana, contexto limitado

Tipo de IA que puede generar contenido nuevo (texto, imágenes, audio, código) basándose en patrones aprendidos de datos de entrenamiento. Se fundamenta en Large Language Models (LLMs) y modelos de difusión. Transformando cómo se crea contenido y desarrollo de software. Los modelos más conocidos son GPT-4, Claude 3, Gemini 1.5, Llama 3.

Deberías saber (basado en roadmaps de AI Engineer, Medium articles, Scaler, arxiv papers):
  • Qué son los LLMs (Large Language Models): modelos de lenguaje con miles de millones de parámetros (GPT-4 con ~1 billón de parámetros, Claude 3 Opus, Gemini 1.5 Pro, Llama 3 8B/70B) que comprenden y generan lenguaje humano a nivel de texto, código y razonamiento
  • Fundamentos: Tokens (unidades de texto, subpalabras, palabrapieces, BPE - Byte Pair Encoding, WordPiece, Unigram tokenization), embeddings (representaciones vectoriales de significado en espacios de alta dimensión, dimensiones típicas: 768, 1536, 4096), attention mechanism (mecanismo de atención que pesa la importancia de diferentes partes del input, self-attention, cross-attention)
  • Ecosistema comercial: "Copilot" concepto, OpenAI GPT series (GPT-3.5, GPT-4, GPT-4o), Anthropic Claude (Haiku, Sonnet, Opus), Google Gemini (1.0, 1.5 Flash/Pro), Llama Models (Llama 2, Llama 3 de Meta)
  • Cómo funcionan a alto nivel: Pre-training en grandes corpus (WebText, Common Crawl, C4, The Pile, Reddit), fine-tuning o prompt engineering para casos de uso específicos, reinforcement learning from human feedback (RLHF) alineación del modelo
  • Casos de uso: Generación de código (GitHub Copilot, código generado, completion de funciones), creación de contenido (blogs, artículos, marketing), resúmenes (documentos extensos, artículos de investigación), chatbots (customer service, support agents), traducción (múltiples idiomas), clasificación (sentimiento, spam, categorías), creatividad (poesía, historias, diseño)
  • Limitaciones: Alucinaciones (información falsa presentada con confianza, tasa de alucinación estimada 3-10% en algunos modelos), sesgo de entrenamiento (sesgos de género, raza, geográficos), costo computacional (costos de entrenamiento millonarios, costos de inferencia por token), contexto limitado (ventana de contexto: 8K, 32K, 128K tokens), dependencia de datos de calidad

Fuente: AI Engineer Roadmap GitHub, Medium "AI Engineer Roadmap for 2026", Scaler Academy contents, arxiv papers 2023-2024, "Attention Is All You Need" (Vaswani et al., 2017)

Prompting y Multimodalidad

Técnica de comunicarse con modelos de IA mediante prompts (instrucciones texto). La multimodalidad permite procesar y generar múltiples tipos de datos (texto, imágenes, audio). Transformando la interacción humano-máquina. Los prompts pueden ser zero-shot, one-shot o few-shot.

Deberías saber (basado en prompt engineering guides, LangChain docs, OpenAI best practices, IBM RAG docs):
  • Prompt engineering básico: ser específico, proporcionar contexto, especificar formato de salida, few-shot (3-5 ejemplos), zero-shot (sin ejemplos), one-shot (un ejemplo)
  • Técnicas avanzadas: chain-of-thought (razonamiento en cadena: "Let's think step by step"), tree-of-thought, auto-com prompting, reflexión y auto-corrección, self-consistency (muestras múltiples respuestas y toma mayoritaria)
  • Multimodalidad: modelos que procesan texto + imágenes (GPT-4V, Claude 3 Opus, Gemini 1.5 Pro con visión), texto + audio (Whisper para transcripción, voice interface), generación de imágenes (DALL-E 3, Stable Diffusion XL, Midjourney v6)
  • APIs clave: OpenAI API (ChatCompletion, completions, embeddings, moderation), Hugging Face inference API, Google AI Studio, GitHub Models, Anthropic API
  • Whisper: modelo de OpenAI para reconocimiento de voz/transcripción, soportando múltiples idiomas (100+ idiomas), formatos (mp3, wav, m4a, flac), precisión variable por idioma
  • Casos de uso: Automatización de reportes (generación automática de reports ejecutivos), creación de contenido visual (diseño, mockups, ilustraciones), análisis de datos hablados (entrevistas, llamadas), accesibilidad (subtítulos, transcripción), asistentes de voz

Frameworks que facilitan el desarrollo de soluciones con IA: RAG (Retrieval-Augmented Generation), fine-tuning, librerías de código (LangChain, LlamaIndex). Organizando y manteniendo proyectos de software que incluyen módulos de IA. RAG es el patrón más importante para aplicaciones empresariales.

Deberías saber (basado en LangChain docs, IBM RAG surveys, SuperML roadmaps, arXiv papers):
  • Qué es RAG y cuándo usarlo: Retrieval-Augmented Generation - combina modelos generativos con recuperación de información externa para fundamentar respuestas en datos reales, reducing hallucinations
  • Diferencia RAG vs fine-tuning: RAG usa datos externos en tiempo real (always up-to-date) vs fine-tuning modifica pesos del modelo entrenado (frozen weights, outdated después del entrenamiento)
  • Componentes RAG: Retriever (busca en vector stores/db - FAISS, Milvus, Pinecone, Weaviate, Chroma, Qdrant), Augmentation (combina query + retrieved context con prompt engineering), Generator (LLM que responde, typically el mismo LLM base)
  • Instalar y configurar LangChain: Python package `langchain`, integrations con OpenAI/Anthropic/Gemini, chains (LLMChain, RouterChain, SequentialChain), agents (React Agent, AgentExecutor), memory
  • LlamaIndex: para creación de índices de datos, query engines, tool integration con fuentes de datos, document loaders, node parser, embedding models
  • Estructurar un proyecto con módulos de IA: separation of concerns, prompts management (prompt files, prompt templates, versionado), vector store selection (basado en casos de uso), evaluation loops (hallucination rate, relevance, factual accuracy)

Filosofía de Uso de Herramientas

No solo aprender comandos, sino entender cómo y cuándo usarlas con criterio. Integrar IA y asistentes sin perder calidad ni visión técnica. El uso estratégico de IA debe balancear productividad y calidad del software. La regla de oro: IA asiste, humano decide.

Deberías saber (basado en mejores prácticas de la industria, thought leaders, Accenture, McKinsey reports):
  • Cuándo usar IA generativa para programar vs escribir código manualmente: casos de uso óptimos (90% de tareas rutinarias pueden ser asistidas, 40% de código puede ser generado automáticamente en algunos proyectos)
  • Validación de código generado por IA: revisión de seguridad, lógica, rendimiento y estilo (code review asistida, security scanning, linters, type checkers)
  • Mantener visión arquitectónica: IA debe seguir patrones y arquitecturas establecidas, no diseñar desde cero sin supervisión (arquitectural guidance, design patterns)
  • Balance productividad/calidad: métricas para medir el impacto de IA en velocity (story points/sprint) y bug rate (reduction vs introduction of new bugs)
  • Evitar dependencia tecnológica: mantener habilidades fundamentales y no delegar todo al asistente (pair programming con IA, code reviews humanas)
  • Responsable AI use: directivas organizacionales, guías de uso ético, transparency en cuándo se usa IA en el código

FASE 6: Flujo de Desarrollo con IA

Desarrollo de Software en la Era de los Agentes NUEVO

IA transformando el desarrollo de software, de asistencia puntual a agentes capaces de investigar, planificar, implementar y validar de forma autónoma. Anatomía de estos agentes: Reasoning (pensar), Acting (usar herramientas), Observing (ver resultados), Memory (retained context). Riesgos: alucinaciones, bucles infinitos, uso indebido de herramientas. Enfoque seguro: límites definidos, human-in-the-loop, evaluaciones de seguridad, monitoring de ejecuciones. Los agentes pueden ser verticales (casos de uso específicos) o horizontales (generalistas).

Deberías saber (basado en LangChain docs, arxiv papers on agentic RAG, Microsoft research, LangGraph):
  • De asistencia puntual a agentes autónomos: evolución de Copilot suggestions (autocomplete) a sistemas que pueden planificar, ejecutar iterativamente y tomar decisiones (agentes planificadores, reasoning engines)
  • Anatomía de agentes: Reasoning (pensar/planificar qué hacer), Acting (usar herramientas/llamar APIs/ejecutar código), Observing (ver resultados/observar output), Memory (memoria de contexto a corto y largo plazo, session memory, persistencia)
  • Patrones ReAct (Reasoning + Acting): bucle Thought → Action → Observation → que agentes iteran hasta resolver (el patrón estándar de la industria)
  • Riesgos: agentes que se salen de pista (off-track agents), bucles infinitos (infinite loops), uso indebido de herramientas (misuse of tools), costos computacionales inesperados (unexpected compute costs)
  • Enfoque seguro: límites definidos (tool use boundaries, scope restrictions), human-in-the-loop (approval nodes, manual gates), evaluaciones de seguridad (security audits, red teaming), monitoring de ejecuciones (execution monitoring, observability, logging)

Contexto, Capacidades y Extensiones para Agentes NUEVO

Diseñar entorno que necesitan los agentes para trabajar eficazmente: contexto, instrucciones, herramientas, permisos y mecanismos de validación. AGENTS.md, Agent Skills, agentes personalizados y MCP, e integrar estos elementos en un agent harness completo para proyecto real. El contexto incluye system prompt, few-shot examples, tool definitions, y más.

Deberías saber (basado en LangGraph docs, MCP specification, LangChain best practices, AutoGen):
  • AGENTS.md: documentación estándar que describe las skills, herramientas y configuración de un agente (formato markdown, descripción de herramientas, variables de entorno, ejemplos)
  • Agent Skills: capacidades específicas que un agente puede ejecutar (búsqueda web, cálculo, archivo, API calls, database queries, file operations, system operations)
  • MCP (Model Context Protocol): estandarización cómo los agentes acceden y comparten contexto con herramientas y memoria (protocol specification, message format, tool definitions)
  • Contexto necesario: system prompts (instrucciones del sistema), few-shot examples (ejemplos few-shot para training), memoria a corto/ largo plazo (working memory, long-term memory, vector store for context)
  • Extensiones: custom tools (herramientas personalizadas, API integrations, database access), integrations with external services (Slack, email, CRM, ERP), file system operations
  • Agent harness: framework para ejecutar agentes con checkpointing (guardar estado), rewind (rewind to previous state), persistence (persistent storage, database), observability (logging, metrics, tracing)
